# Feature Suggestions Report — Termux Companion

> Generated by static analysis of the full Kotlin source tree (`app/src/main/java/com/termux/companion/`),
> build config, and manifest on 2026-08-26. No build or instrumented run was performed.
>
> **Stack**: Kotlin 2.0.20 · Jetpack Compose (BOM 2024.09.00) · Hilt 2.52 · Room 2.6.1 · DataStore 1.1.1 · OkHttp/Retrofit
> **Scope**: 30 Kotlin files across `data/`, `domain/`, `ui/`, `widget/`, `di/`, `utils/`.

---

## Executive Summary

Termux Companion is a well-structured MVVM app, but several **UI affordances are non-functional stubs**
(file rename/delete/create, editor search), one core integration path has a **double-execution bug**,
and a number of high-value features (history browser, snippets, configurable widget) are half-built —
the data layer already exists but no UI consumes it.

Three findings gate other work and are listed first as **Foundation Fixes**, followed by prioritized
feature suggestions with impact/effort/confidence ratings.

## Foundation Fixes (gate the features below)

| ID | Issue | Location | Detail |
|----|-------|----------|--------|
| FIX-001 | **Every command executes twice** | `data/termux/TermuxCommandExecutor.kt:79-80` | `executeWithResult()` calls both `sendToTermuxWithPI(command, …)` (original command) *and* `sendToTermux(wrapped, …)` (wrapped command). Both reach Termux's `RUN_COMMAND` service, so side-effecting commands (`pkg install`, `rm`, writes) run twice. Pick one delivery path; use the PendingIntent result bundle as primary since it avoids shared-storage round-trips. |
| FIX-002 | **Result receiver is exported & spoofable** | `data/termux/TermuxResultReceiver.kt:62` | Registered with `RECEIVER_EXPORTED` for action `com.termux.companion.TERMUX_RESULT`. Any app can broadcast fake results (e.g., forged "exit code 0"). Use `RECEIVER_NOT_EXPORTED` — Termux delivers results via PendingIntent created by this app, so no export is needed. |
| FIX-003 | **API key stored in plaintext** | `data/settings/SettingsRepository.kt:71-73` | LLM API key sits in plain DataStore prefs, readable via backup (`allowBackup="true"` in manifest). Encrypt with Android Keystore (or `androidx.security:security-crypto`) and exclude secrets from backup rules. |
| FIX-004 | **Diagnostics always fail** | `data/termux/TermuxDiagnosticsChecker.kt:44-53` | `Runtime.exec("grep … /data/data/com.termux/…")` reads another app's private dir — always fails without root, so `allowExternalApps` is always `false`. Replace with a round-trip probe: send `echo tc-probe-$id` through the executor and verify the result arrives. |
| FIX-005 | **Unsafe shell construction** | `EditorViewModel.kt:116`, `FileExplorerViewModel.kt:57`, `SecurityRepository.kt:115` | Paths/content interpolated into shell strings break on quotes/newlines; heredoc save corrupts files containing `TC_EOF`; large saves exceed the ~1 MB Binder intent limit and crash. Base64-encode payloads (`echo <b64> \| base64 -d > "$path"`) and single-quote-escape paths. |
| FIX-006 | **Duplicate history rows accumulate** | `data/db/CommandHistoryEntity.kt` + `TerminalViewModel.kt:110-117` | `insert(REPLACE)` always creates a new row (auto-gen id), then `incrementUseCount` updates *all* rows with that command. Add a unique index on `command` and upsert instead. |
| FIX-007 | **Thread-unsafe static state** | `TermuxCommandExecutor.kt:34-40` | `nextId` / `callbacks` are mutable statics in the companion object. Move to instance fields with `ConcurrentHashMap` (also fixes leaks if callbacks outlive ViewModels). |
| FIX-008 | **Orphaned temp files in Downloads** | `TermuxCommandExecutor.kt:74-75` | `tc-out-*.txt` / `tc-done-*.txt` leak if the process dies mid-poll; they also expose command output (possibly secrets) in shared storage. Sweep stale files on startup and prefer the PI path (FIX-001) to eliminate them. |

## Priority Reasoning

- **FEAT-001–003 first**: they convert existing dead UI/stubs into working features users will immediately try (rename/delete, history, find-and-replace). Effort is contained because the execution pipeline already works.
- **FIX-001 before any "run command" feature expansion**: double execution silently corrupts stateful operations (`pkg install`, file copies, wallet-mode `settings put`).
- **Security items (FIX-002/003, FEAT-005)** are cheap relative to their risk: spoofable results, plaintext keys, and an unguarded arbitrary-command surface.
- **Medium tier** grows the product (packages, processes, ANSI) but depends on stable foundations (FIX-001/005, FEAT-008 tests).

## Analysis Limitations

- Static review only — no Gradle build, no device/emulator run, so runtime behavior of the Termux IPC paths (file polling vs. plugin bundle) was inferred from code and Termux docs referenced in comments.
- `assets/commands.json` contents were not validated against the autocomplete consumer schema.
- Widget layout XML (`res/layout/widget_termux.xml`) reviewed by reference only.
